# GPT-6 모델별 검수 입력 조정

확인일: 2026-09-24. 이 문서는 모델 라우팅 규칙이 아니라 사용자가 이미 선택한 모델에 맞춰 검수 입력을 정리하는 보조 지침이다. 해당 모델 절만 필요할 때 읽는다.

## 공식 자료와 이 패키지의 설계 구분

OpenAI의 GPT-6 공통 가이드는 Astra·Sol·Luna에 공통 출발점을 제공하지만, 설명한 행동 특성은 Astra에서 관찰된 것이므로 선택 모델과 작업에서 평가하라고 명시한다. 세 모델 각각의 비공개 시스템 프롬프트를 확인한 것이 아니다.[S2]

모델 카드의 공개 성격과 공식 공통 지침을 아래 검수 입력 형태로 적용했다. 아래의 체크 순서·역할 연결은 이 패키지의 설계이며 공식적인 모델별 전용 검수 시스템 프롬프트가 아니다. 역할이나 판정 기준을 모델에 따라 느슨하게 바꾸지 않는다.

## GPT-6 Luna — `gpt-6-luna`

공식 모델 카드는 효율적인 좁은 범위·반복 가능한 작업을 중심으로 설명한다.[S3]

선택된 모델이 Luna이면 변경 파일과 직접 관련 계약, 필수 기준, 실제 증거 위치를 작게 묶는다. 모호한 전체 저장소 감사나 “좋아질 때까지 최적화” 요청을 하지 않는다. 경계 사례는 이번 변경의 입력·상태와 연결해서 전달하고 반환 계약을 명확히 한다. 판단할 근거가 부족하면 최소 증거를 요청하거나 `INCONCLUSIVE`로 남긴다. 넓은 탐색·다른 모델로의 승격을 스스로 시작하지 않는다.

## GPT-6 Sol — `gpt-6-sol`

공식 모델 카드는 복잡한 코딩·에이전트 작업의 강한 추론 모델로 설명한다.[S4]

선택된 모델이 Sol이면 변경 코드와 직접 연결된 호출자·계약·테스트·실패 경로를 함께 준다. 단일 줄의 스타일보다 비동기 순서·권한/데이터 경계·상태 변화·회귀를 확인하도록 완료 기준을 정한다. 성능은 실제 호출/추적/측정으로 뒷받침하고, 코드를 고쳐 문제를 “해결한 다음 통과”시키지 않도록 읽기 전용 계약을 유지한다.

## GPT-6 Astra — `gpt-6-astra`

공식 모델 카드는 높은 난도의 추론·코딩·컴퓨터 사용을 다루며, 공통 가이드는 지침의 모호성, 서브 위임 조건, 작은 작업의 과도한 검증을 점검하도록 안내한다.[S2][S5]

선택된 모델이 Astra이면 기대하는 사용자 결과·고정 조건·검수 범위·필수 증거·종료 조건을 우선한다. 이미 정한 제품 동작은 다시 묻지 않게 하고, 범위 밖 재설계나 무한 검수로 확대하지 않게 한다. 메인에게는 언제 검수를 호출할지 명시하고, 서브에게는 추가 위임을 금지한다. 이미지·흐름·코드 증거를 함께 보더라도 자기 역할의 관점으로 판정하며 상대 역할을 다시 구현하지 않는다.

## 모델·effort·Ultra 보존

TOML에서 `model`과 `model_reasoning_effort`를 지정하지 않았다. 공식 문서상 별도 지정이 없다면 호출의 명시값·서브 기본값·부모값 등 현재 설정의 해석을 따른다. 따라서 “무조건 메인과 같은 모델”이라고 보장하지 말고 실제 선택값을 확인한다.[S1]

이 설치본의 사용자 정책은 검수 역할을 지원되는 GPT-6 Astra 또는 GPT-6 Sol과 기본 effort `high`로 시작하는 것이다(`AGENTS.md` 7절 모델과 위임). 해당 역할에 대한 사용자 지정이 있으면 이를 우선한다. 모델·effort를 실제 호출에 명시하고 유효 설정과 실행기가 제공한 선택값을 확인한다. 메인 모델만의 지정을 검수 모델 지정으로 확대하지 않는다. 고정 TOML이 없어도 요청값이 실제 적용된다고 가정하지 않는다. 상향은 근거와 실행기 지원이 있을 때만 한다. 이 기본값은 공식 필수 배정표가 아니라 사용자 운영 정책이다.

Astra의 `none` 미지원 등 모델별 차이가 있으므로 effort 이름을 공통이라고 가정하지 않는다.[S2] UI의 Ultra와 API/로컬 설정의 `ultra`, `max`, `xhigh`를 문서나 실제 런타임 매핑 확인 없이 동일한 값으로 치환하지 않는다. 모델 가용성은 계정·실행 환경에서 별도 확인하며 미지원이면 보고한다. 계정 전환·pool 재설정·과금 선택은 하지 않는다.

## 로컬 목록과 실제 호출

모델 가이드의 ID를 현재 실행기의 활성 카탈로그나 실제 호출 성공으로 대신하지 않는다. 사용자가 제공한 `~/.codex/opencodex-catalog.json` 확인 보고에는 `gpt-6-luna`, `gpt-6-sol`, `gpt-6-astra`가 있다고 되어 있다. 이는 사용자 환경의 보고이며 이 패키지 작성 환경에서 해당 Mac을 직접 조사한 결과는 아니다. 다른 제품의 에이전트 목록과 섞지 않는다.

선택된 실행기·버전·활성 프로필과 실제 로딩된 카탈로그, 호출에 사용된 모델/effort를 필요한 때만 확인한다. 같은 이름의 카탈로그 파일이 있다는 것만으로 실제 선택·접근 권한·성공을 확정하지 않는다. 모델 버전을 자동 치환하거나 계정·pool을 변경하지 않는다.

## 성능 평가는 별도

같은 요구·변경·증거·권한·완료 기준을 유지하고 선택 모델과 effort만 의도적으로 바꿔 비교한다. 놓친 실제 결함·잘못된 차단·증거 없는 주장·무단 쓰기·재검수 횟수와 실제 로그의 시간·토큰·비용을 기록한다. 결함 수가 많거나 긴 답을 했다는 이유로 점수를 높이지 않는다. 이 패키지는 해당 모델들의 실제 비교 실험을 수행한 결과가 아니다.
