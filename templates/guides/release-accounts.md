# TestFlight·계정 식별

## 13. TestFlight

적용 조건: 이미 TestFlight에 등록된 앱의 수정으로 앱 동작 또는 배포 산출물이 달라지는 경우. 신규 앱의 등록·배포는 별도 사용자 요청이나 승인을 따른다.

- 적용 조건을 충족하면 개발과 검증을 마친 뒤 새 빌드를 업로드한다. 이는 상시 승인된 작업이며 사용자가 배포 제외를 명시한 경우에는 업로드하지 않는다. 문서만 바뀌어 배포 산출물에 영향이 없으면 업로드하지 않는다.
- 이 승인을 App Store 출시나 테스터·배포 설정 변경 승인으로 확대하지 않는다.
- 업로드 전 기존 변경의 배포 포함 범위를 확인한다. 출처나 승인이 불명확한 변경을 섞지 않는다. 분리할 수 없으면 기존 작업을 훼손하지 말고 업로드만 보류한 뒤 필요한 조치를 보고한다.
- 업로드 전 공통 검증과 필요한 시뮬레이터 조작·시각 검수, 7절에서 해당 변경에 요구하는 독립 검수를 충족한다. 필수 검증이 남으면 업로드를 보류한다. 버전·빌드 번호·번들 식별자·서명·환경·비밀값 노출·의도치 않은 dev/mock 활성화를 확인한다. 검증한 소스·설정과 업로드 산출물의 대응을 확인한다.
- 필요하면 빌드 번호를 올리고 이미 업로드한 번호를 재사용하지 않는다. 실패나 타임아웃만으로 번호를 계속 올리지 말고 원격 반영 여부를 먼저 확인한다.
- 업로드 성공 여부를 실제 응답이나 상태로 확인한다. 업로드 성공을 TestFlight 처리 완료·테스터 배포 완료로 대신 표시하지 않는다.
- 로그인, 2단계 인증, 인증서, 서명이 업로드를 막으면 필요한 수동 조치를 보고하고 배포 완료로 표시하지 않는다.
- 완료 보고에는 공통 보고 항목과 함께 버전/빌드, TestFlight 업로드 결과, 확인된 처리 상태를 포함한다.
