# 제품·UI·데이터

## 9. 제품·UI·데이터

적용 조건: 제품 동작, 아키텍처, 화면 또는 데이터 흐름을 설계·구현·수정·검증하는 작업.

- 규모·아키텍처를 판단할 때 장기적으로 100만 MAU를 고려하되, 현재 단계와 측정된 필요에 맞게 구현한다. 예상 규모만으로 복잡한 구조를 추가하지 않는다.
- 처음부터 다국어를 지원한다. 기존 프로젝트는 현재 지원 언어와 번역 체계에 변경을 반영하고, 내부 enum·sentinel 값·번역되지 않은 키를 화면에 노출하지 않는다. 작은 수정에 무관한 전체 번역 재구성을 끼워 넣지 않는다.
- 관련 프로토타입의 레이아웃·동작·상태를 확인한다.
- 기존 테마·디자인 토큰·공용 컴포넌트를 재사용하고 같은 역할의 컨트롤을 일관되게 만든다. 터치 영역은 iOS 최소 44×44pt, Android 최소 48×48dp를 지킨다. 시각적 크기와 터치 영역을 구분하고 더 엄격한 기존 규격은 유지한다.
- 변경 영향이 있는 로딩·빈 화면·오류·비활성·복구 상태를 확인한다. 직접 진입에도 뒤로·닫기·취소 동작이 안전한 목적지로 가게 한다.
- 구조화된 데이터·접근·변환 로직은 UI 밖에 두고 기존 계층을 따른다. 신규 흐름의 기본은 `JSON/API → Repository → Model → UI`이며 무관한 계층 재구성은 하지 않는다. 계산값은 숫자로 보관하고 공통 데이터를 재사용한다.
- 목업과 실제 데이터를 분리한다. 하나의 흐름에서 가짜 계정 데이터와 실제 계정 데이터를 섞거나 목업 쓰기를 원격 저장처럼 보이게 하지 않는다.
- 이미지 좌표는 원본 크기를 기준으로 확인한다. 스프라이트 메타데이터나 확인된 경계를 쓰고 잘림과 인접 픽셀 혼입을 검사한다.

### 화면 비교와 스크린샷

- 가능하면 같은 기기·언어·테마·계정/데이터 상태에서 수정 전후 화면을 캡처하고 완료 보고에 둘 다 포함한다. 조건이 다르거나 캡처가 불가능하면 이유를 밝힌다. 스크린샷만으로 동작 검증을 대신하지 않는다.
- 임시 스크린샷은 `tmp/screenshots/` 또는 `.codex/screenshots/`에 둔다.
- 스크린샷은 `FEATURE_한국어화면` 형식으로 이름 짓고, 필요할 때만 의미 있는 상태·플랫폼 접미사를 붙인다. 동일 화면은 같은 태그를 사용하고 비교에는 `_수정전`, `_수정후`를 쓴다.
